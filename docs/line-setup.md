# LINE注文の設定手順（担当者向け）

お客さんが LINE から自社に注文できるようにするための設定です。
全部で **5つの作業**、時間は 30〜40分ほどです。

- ログイン・アカウント作成・規約への同意・パスワードの入力は、**担当者ご本人**にしていただきます。
- Claude は、ページを開くところまでお手伝いします。
- 出てくる「チャネルシークレット」「アクセストークン」は、**合いかぎ**のようなものです。
  人に見せたり、メールやチャットに貼ったりしないでください。貼る場所は `.env.local` というファイルだけです。

> LINE がまだつながっていなくても、デモはできます（いちばん下の「LINEなしで試す」）。

---

## 作業1　LINE公式アカウントを作る（10分）

1. Chrome で **https://entry.line.biz/start/jp/** を開きます。
2. 「LINE公式アカウントをはじめる」→「アカウントを作成」を押します。
3. LINE のアカウント（またはメールアドレス）でログインします。**← 担当者が入力**
4. 入力する内容
   - アカウント名：`自社 ご注文窓口`（お客さんのLINEに出る名前。あとで変えられます）
   - 会社・事業者の所在国・地域：日本
   - 会社・事業者名：（応募した会社）
   - 業種：小売・卸 → 食品（近いもので大丈夫です）
5. 規約を読んで同意し、「完了」を押します。**← 担当者が同意**
6. 「LINE Official Account Manager へ」を押すと、管理画面が開きます。

## 作業2　Messaging API を使えるようにする（5分）

LINE で届いた文章を、受発注ハブで受け取るための設定です。

1. 管理画面の右上の **「設定」** を押します。
2. 左のメニューの **「Messaging API」** →「Messaging APIを利用する」を押します。
3. 開発者情報（名前・メール）を入れ、規約に同意します。**← 担当者が同意**
4. 「プロバイダー」を聞かれたら「プロバイダーを作成」→ 名前は `（応募した会社）`。
5. プライバシーポリシー・利用規約のURLは空欄のまま「OK」で進みます。

### 自動の返事を止める

ハブが返事をするので、LINEの自動返事は止めます（返事が二重にならないように）。

1. 管理画面の「設定」→ 左の **「応答設定」** を開きます。
2. 次のとおりにします。
   - チャット：オフ
   - あいさつメッセージ：オフ
   - Webhook：**オン**
   - 応答メッセージ：**オフ**

## 作業3　合いかぎ（シークレットとトークン）を `.env.local` に貼る（5分）

1. Chrome で **https://developers.line.biz/console/** を開き、同じ LINE でログインします。**← 担当者が入力**
2. プロバイダー「（応募した会社）」→ チャネル「自社 ご注文窓口」を押します。
3. **「チャネル基本設定」** タブの下の方にある **「チャネルシークレット」** をコピーします。
4. メモ帳で `C:\work\juhacchu-hub\.env.local` を開き、次の行を足して貼ります。
   ```
   LINE_CHANNEL_SECRET=（ここに貼る）
   ```
5. **「Messaging API設定」** タブのいちばん下 **「チャネルアクセストークン（長期）」** の「発行」を押し、出てきた文字をコピーします。
6. `.env.local` に次の行を足して貼り、保存します。
   ```
   LINE_CHANNEL_ACCESS_TOKEN=（ここに貼る）
   ```

> `.env.local` は git（公開リポジトリ）には入らない設定になっています。

## 作業4　注文フォーム（LIFF）を作る（10分）

お客さんが LINE の中で、商品を選んで＋−で数を入れるだけの注文画面です。

1. LINE Developers の画面で、プロバイダー「（応募した会社）」を開きます。
2. 「新規チャネル作成」→ **「LINEログイン」** を選びます。
   - チャネル名：`自社 注文フォーム`
   - チャネル説明：`パンのご注文フォーム`
   - アプリタイプ：**ウェブアプリ** にチェック
   - メール：担当者のメール
   - 規約に同意して「作成」。**← 担当者が同意**
3. できたチャネルの **「チャネル基本設定」** にある **「チャネルID」**（数字）をコピーして、`.env.local` に足します。
   ```
   LINE_LOGIN_CHANNEL_ID=（ここに貼る）
   ```
4. 同じチャネルの **「LIFF」** タブ →「追加」を押します。
   - LIFFアプリ名：`ご注文`
   - サイズ：**Full**
   - エンドポイントURL：`https://（公開URL）/liff/order` ← 作業5で決まるURL。Claude がお伝えします
   - Scope：`openid` と `profile` にチェック
   - 友だち追加オプション：**On (Aggressive)**（フォームを開いた人に、公式アカウントの友だち追加をすすめる）
   - 「追加」を押します。
5. 一覧に出た **「LIFF ID」**（`1234567890-abcdefgh` のような形）をコピーして、`.env.local` に足します。
   ```
   NEXT_PUBLIC_LIFF_ID=（ここに貼る）
   ```
6. チャネルの上にある **「開発中」** を押して **「公開」** にします。
   （開発中のままだと、担当者以外は注文フォームを開けません）

## 作業5　Webhook の URL を入れる（5分・Claude と一緒に）

LINE は「インターネットから見えるURL」にしかメッセージを届けられません。
いまの受発注ハブは担当者のパソコンの中だけで動いているので、
**トンネル**（パソコンの中のハブに、一時的な公開URLを付ける道具）を使います。

- 使う道具：**cloudflared**（Cloudflare社の無料ツール。アカウント登録なしで使えます）
- 一時的なURLなので、**パソコンを閉じると届かなくなります**。デモと試しの間だけ使います。
- 本番で使うときは、ハブをインターネット上のサーバーに置きます（あとで決めます）。

手順

1. トンネルは担当者が起動します。出てきた `https://xxxx.trycloudflare.com` のURLは管理役から伝わります。
2. LINE Developers →「自社 ご注文窓口」→ **「Messaging API設定」** タブ を開きます。
3. **Webhook URL** の「編集」を押し、`https://xxxx.trycloudflare.com/api/line/webhook` を入れて「更新」。
4. **「検証」** を押して「成功」と出ればOKです。
5. **「Webhookの利用」** をオンにします。
6. 作業4の LIFF の「エンドポイントURL」も、`https://xxxx.trycloudflare.com/liff/order` に直します。

> **注意：cloudflared のURLは起動するたびに変わります。** パソコンの再起動のあとや**動画の撮影日**など、トンネルを起動し直したら、必ず 3〜4（Webhook URL と検証）と 6（LIFF のエンドポイントURL）を新しいURLでやり直します。
> リッチメニューのリンク（`https://liff.line.me/（LIFF ID）`）と `.env.local` は変わらないので、やり直さなくてよいです。

## さいごに：お客さんへの見せ方

1. LINE Official Account Manager →「ホーム」→ 左の **「リッチメニュー」** →「作成」。
2. テンプレートは大きいボタン1つ（または2つ）を選び、
   - ボタン1：タイプ「リンク」、URL は `https://liff.line.me/（LIFF ID）`、文字は **「注文する」**
3. 表示期間を入れて「保存」。トーク画面の下に「注文する」ボタンが出ます。
4. 友だち追加のQRコードは「ホーム」→「友だちを増やす」→「友だち追加ガイド」にあります。
   ドライバーさんに印刷して配ってもらえます。

## はじめてのお客さんのひも付け（毎回ではなく、初回だけ）

- LINE の人が「どのお店か」は、はじめは分かりません。
- 初めて注文が来たら、受注一覧に「得意先：未確認」として入ります。
  お店の名前（フォームで入れてもらったもの）を見て、スタッフが得意先を1回選びます。
- 2回目からは自動でそのお店の注文になります。

## 確定の連絡

- スタッフが受注一覧で「確定」を押したときだけ、お客さんへ
  「ご注文を確定しました」と内容の一覧が LINE で届きます。
- 自動では送りません。

## LINEなしで試す（デモ用）

LINE の設定がまだでも、架空のメッセージを流し込んで試せます。

```bash
npm run dev -- -p 3103
```

別の画面で:

```bash
node scripts/line-webhook-test.mjs
```

```bash
node scripts/line-webhook-test.mjs "明日 ロール 20個、食パン6枚切り 2本"
```

- 注文フォームは http://localhost:3103/liff/order?demoUser=U_demo_kotori で開けます。
- 届いた注文は受注一覧（`data/db.json`）に「要確認」で入ります。
- お客さんへ返したはずの文面は `data/line.json` の `outbox` に残ります（デモでは実際には送りません）。

## 設定の状態を確かめる

http://localhost:3103/api/line/webhook を開くと、どの値が入っているかが分かります（値そのものは出ません）。
`"mode": "live"` なら本物の LINE につながっています。

## 撮影日の起動（デモの時計）

撮影日は、受発注ハブの「いま」を **2026年11月5日 11:30** に合わせて動かします。
LINE で「明日」と送ると 11/6 として読み、注文フォームの日付カードも 11/5 を基準に並びます。

**撮影の前**
1. `C:\work\juhacchu-hub\.env.local` の最後に、次の2行を足して保存します。
   ```
   DEMO_NOW=2026-11-05T11:30:00+09:00
   NEXT_PUBLIC_DEMO_NOW=2026-11-05T11:30:00+09:00
   ```
   - `DEMO_NOW` はサーバー側の時計です（LINE の受信日時、「明日」の基準、受注一覧）。
   - `NEXT_PUBLIC_DEMO_NOW` は画面側の時計です（注文フォームの日付カード、締め切りの判定）。**必ず2つとも同じ値**にします。片方だけだと、画面とサーバーで日付がずれます。
2. 開発サーバー（3100）を**起動し直します**。時計は起動した瞬間に 11:30 から始まり、本物と同じ速さで進みます。
3. トンネル（cloudflared）を起動し直したときは、URL が変わります。作業5の 3〜4（Webhook URL と検証）と 6（LIFF のエンドポイントURL）を、新しいURLでやり直します。
4. 確かめ方：受注一覧の日付が 11/5 になっていること。注文フォームで「あした」が 11/6（金）になっていること。

**撮影の後**
1. `.env.local` から、足した2行（`DEMO_NOW` と `NEXT_PUBLIC_DEMO_NOW`）を消して保存します。
2. 開発サーバーを起動し直します。本物の時計に戻ります。

> 撮影中にデモのリセットを押すと、本番の LINE から届いた注文も消えます。残したい注文があるときは、リセットの前に確認を済ませてください。
