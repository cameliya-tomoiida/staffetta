# UX メモ（②デザイン・2026-11-05）

`docs/ux-brief-codex.md` の「使う人5人」になりきって各画面を使い、困った点と直したことを書く。
タブレット横（1024）とスマホ（375）で確かめた。

## 1. 使ってみて困った点

### 事務の女性（60代）
- 開いても「今日、何件確かめればいいか」がすぐ分からない。FAX受信箱・受注一覧・LINE受付をそれぞれ開かないと、要確認の件数が分からない。
- 受注一覧は、上の絞り込みの箱が大きくて、注文が画面の下に押し出される。開いた瞬間に注文が見えない。
- メニューが7つに増え、タブレットの横幅で右端（発注書・送り出し）が切れて見えない。
- 要確認の理由がむずかしい（「概数」「対応が推測」「様式」）。
- 数量の横に単位が小さく付いていて、「12P」と「120個」のどちらが本当の数か迷う。

### 営業課長（50代・夕方に急いでいる）
- 締め時刻までの残りが、発注書の画面を開いて下まで見ないと分からない。いちばん急ぐ仕入先が上に来ていない。
- 「まだ確定していない注文」がいくつあるか、発注書の画面からは分からない（確定前に発注すると数がずれる）。
- 発注書が8枚並ぶと、承認待ちがどれか探しにくい。

### 製造の現場スタッフ（外国人・朝5時・手が粉で汚れている）
- 製造計画の画面を開くと、ことばの選ぶ箱が大きく、作る数と時間割が下に押し出される。
- 毎朝、自分の言葉を選び直さないといけない（タブレットが覚えていない）。
- 管理者向けのお金の枠や、日本語の注意が、作る数より上にある。
- 時刻の目盛りに「前日」「翌」の日本語が残る。単位「本」「袋」「c/s」が訳されない。

### 工場長（60代）
- 材料が足りるか（発注書の材料）と、ピザの上限超えの注意が別の画面に分かれている。今回はトップの帯に「注意」の件数を出すだけにする（全体を見る画面は次の段階）。

### お客さん（LINE・70代）
- LIFF の注文画面（④）は大きなボタンで分かりやすい。「締め切りを すぎています」が日付ボタンの中に小さく出るので、押せないことに気づきにくい → ④への提案。

## 2. 直したこと（理由）

- **全画面の上に「今日やること」の帯**：要確認の注文・FAX の確認待ち・承認待ちの発注書・次の締めまでの残り を、どの画面でも開いた瞬間に出す。押すとその画面へ行く。（事務・課長）
- **メニューを2段に**：上の段に名前と今日の帯、下の段にメニュー7つ。タブレット横で全部見える。流れの順（受ける → まとめる → 作る → 頼む）に並べた。（事務）
- **受注一覧**：上に「要確認／仮発注／確定／取消」の件数を大きく出す。絞り込みは「状態」だけを常に見せ、ほかは「くわしく絞り込む」で開く。URL の `?status=needs_review` で要確認だけを開ける（帯から1タップ）。（事務）
- **発注書**：締めの早い順に並べる。上に「承認待ち○枚・いちばん近い締め」を出す。確定していない注文があれば「まだ確定していない注文が○件あります」と出す。（課長）
- **製造計画**：ことばの選び方を小さな1行に。選んだ言葉はタブレットが覚える（次に開いたときも同じ言葉）。お金の枠は下へ。（現場）
- **多言語**：単位（本・袋・P・c/s）と「翌／前日」を辞書に足した。機械翻訳で数字がその国の数字に変わらないように、翻訳のたのみ方に「数字と単位は変えない」と用語集を足した。（現場）
- **要確認の文言**：`docs/wording.md` の言いかえを、画面に出る文に反映（②が書いている文と、画面で出す前の言いかえ）。（事務）

## 3. ①（FAX）への提案（コードは変えていない）

- FAX受信箱（`/`）の状態の札（`bg-amber-200` など）を、共通部品 `Tag` / `OrderStatusTag` にそろえると、ほかの画面と色の意味がそろう。
- 確認画面の「読み取りの自信が低め（62%）」は、% をやめて「字が 読みにくい ところが あります」に（`docs/wording.md`）。
- 確認画面の「⚠」の絵文字は、共通部品の `Icon.alert` に。
- FAXの縮小画像が読み込み中のとき、灰色の箱だけになる。「読み込み中」の文字か、発信元の大きな文字を先に出すと、何のFAXか分かる。

## 4. ④（LINE）への提案

- LIFF の日付ボタン：締め切りを過ぎた日は、ボタンをうすくして押せないことが分かるように。
- LINE受付でお客さんをお店にひも付けたとき、そのお客さんの「お店が不明」の注文にも、お店を入れる（今は受注一覧の確定で選び直している）。

## 5. 直せなかった点・次の段階

- **工場長向けの全体の画面が無い**：材料が足りるか（発注書の材料）、ピザの上限超え、人が足りるか（工程表の のべ作業時間）が、別々の画面に分かれている。次の段階で「1日の全体」画面を作る（③の `scheduleSummary` の のべ作業分と、`dayCostSummary` を1枚に）。今はトップの帯に「注意 ○件」を出すだけ。
- **現場向けの注意が日本語のまま**：ピザの上限超え・「前日○時に始める必要」などの注意は、③の warnings が日本語の文なので訳せない。③に「コードと数字」を持たせてもらえば、辞書から各言語の文を組み立てられる（`docs/i18n-todo.md`）。
- **要確認の理由の言いかえは、画面に出す直前の置きかえ**：入口ごとの取り込み（①④⑤）が新しい言い方で書くようになれば、置きかえは要らなくなる。理由のコード（`ReadValue.reasons`）は types.ts の変更になるので見送った（`docs/wording.md`）。
- **FAX受信箱（トップ）と確認画面**は①の担当なので、共通部品へのそろえ（状態の札・%表示・絵文字）は提案だけ（3. を参照）。
- **変更・取消の連絡の確定**：受注一覧からは確定できない（元の注文の書きかえが要る）。FAX は①の確認画面でできるが、LINE・メールの変更は、元の注文と並べて見比べる画面がまだ無い。
- **発注書の「承認を取り消す」**：③の保存の決まりに「取り消し」が無いので、ボタンを外した。まちがえて承認したときの戻し方を③と決める。
- **辞書の訳の確認**：9言語の訳はどれも Claude の下書き。各国のスタッフに工程表の印刷を見てもらい、確かめた訳から「機械翻訳」の印を外す仕組み（machine.json に reviewed）を作る。
- **ことばの選び直し**：タブレットは選んだことばを覚えるが、1台を何人かで使うときは毎回切りかえが要る。名前のボタン（グエンさん → ベトナム語）で選べるとよい。
- **印刷**：A4 の幅で画面に当てて確かめただけで、本物のプリンタ・複合機の FAX ではまだ試していない。
- **お金の枠**：材料費・仕入額・粗利は ③の架空の単価での目安。税込・税抜の切りかえや、月の合計は無い。
