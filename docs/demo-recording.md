# デモ動画の画面録画の手順（⑧ → ⑥）

1つの FAX（F001・ひまわり保育園（架空）の週間パン注文表）を、届いてから分析まで追って撮ります。
**本番（3100）の DB は使いません。** 見本の DB のコピーで確認用サーバーを立て、撮り終わったらすぐ止めます。

| ファイル | 撮るもの |
|---|---|
| D1_fax到着 | 受信箱に F001 が届く（撮影中に「届いた」状態で入れる。受信箱が数秒おきに見て、知らせて並べ直す） |
| D2_fax読取 | F001 を開く → 「AI が FAX を読んでいます」→ 迷った行（黒糖ロール 訂正あり 20→25）だけ黄色で残る |
| D3_確認して注文に | 黄色の行の数を入れ直す → 「見比べた」→ 確定 → 受注一覧（入口の印 FAX・LINE・電話 が並ぶ）にその注文 |
| D4_製造計画 | その注文の日の製造計画 → 「ベトナム語に変換」 |
| D5_発注書 | 「超じゅくロール 6個入 65個 → 11袋」の行 |
| D6_配送 | コースの見直し（数字が回る → ピンが落ちる・線が伸びる・着く時刻）→ 今のコースと切りかえ |
| D7_製品カードと衛生 | 製品カードの形（見たまま編集）→ 温度の記録 → 記録の漏れ |
| D8_分析 | 分析（司令室）。数字が数え上がり、グラフが描かれる |
| D9_ホーム | 管理者のホーム |

## 1. 撮影のもと（1回だけ。本物の AI を1回使う）

F001 を本物の AI に読ませた結果を `data/demo-f001.json` に取っておきます（撮り直しのたびに AI を呼ばないため）。

1. 見本の DB のコピーで確認用サーバーを立てる（`.claude/launch.json` に `HUB_DB_PATH=data/demo-record.sqlite`・`HUB_SCHEDULER=off` の設定を一時的に足す）
2. 受信箱で F001 の「Claudeで読み取る」を押す
3. `python -I scripts/demo-record/prepare.py snapshot data/demo-record.sqlite`

## 2. 撮る

1. サーバーを止めてから、撮影用の DB を作り直す（F001 は「まだ届いていない」状態）:
   `python -I scripts/demo-record/prepare.py fresh <見本の DB> data/demo-record.sqlite`
2. 確認用サーバーを立てる（できれば `next build` → `next start`。開発用サーバーより軽く、「Rendering…」の印も出ない。開発用でも撮れるが、メモリが少ないと「読み込み中…」が映る）
3. `python -I scripts/demo-record/record.py <出力フォルダ> data/demo-record.sqlite [--only D3,D6]`
   - D1 の中で `prepare.py arrive`（F001 が届く）、D2 の前に `prepare.py autoread`（AI が読み終えた状態にする。工場では届くと自動で読む）を呼ぶ
   - 1920×1080・30fps の mp4 と、最後の画面の png を出す
   - 開発用の「Rendering…」の印は、録画の中で消す
4. 撮り終わったら、すぐにサーバーとブラウザを止める。`.claude/launch.json` を元に戻す

撮り直しは `--only` で場面を選べます。D3 から先は、D1・D2 で F001 が入っている DB で撮ります（`fresh` は D1 から撮り直すときだけ）。
