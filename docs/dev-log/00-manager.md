# 00 管理役 — 開発の進め方の記録

非エンジニアの専務（作者）が、**音声入力だけ**で Claude Code に指示を出して作りました。作者はコードを1行も書いていません。

## 1. 体制：管理役＋担当6つの並行セッション

| 担当 | やったこと | 作業場所 |
|---|---|---|
| 管理役 | 業務の聞き取りと調査、担当の割り振り、質問への回答、マージ、見回り | このリポジトリの外（企画フォルダ） |
| ① 土台・FAX | 共通の型、SQLite、FAX の読み取りと確認画面、Gmail→GAS→受け口、名寄せ辞書 | master（本体フォルダ） |
| ② 画面 | 左メニュー、共通部品、管理画面の枠、工程表の言語タブと印刷、10言語 | git worktree |
| ③ 計算 | 集計・入数換算・発注書・製造計画・設備と人員の制約・材料・原価、検証役 | git worktree |
| ④ LINE | LINE 公式アカウント、LIFF の注文画面、トーク読み取り、取引先とのひも付け | git worktree |
| ⑤ 外部サイト | メール・シート・CSV の取り込み、発注の送り出し、マスタの CSV 一括登録 | git worktree |
| ⑥ 動画 | 構成・台本・合成音声・自作 BGM・演出・撮影の自動化 | 企画フォルダ |

- 担当どうしは **セッション間のメッセージ（SendMessage）** で直接やりとりし、共通の型やマスタの形は管理役を通して決めました。
- 各担当は自分の **git worktree（別ブランチ）** で作業し、管理役がテスト・型チェック・lint を通してから master にマージしました（衝突したら担当が解消）。
- 管理役は **30分おきの見回り（スケジュール実行）** で、止まっているセッション・マージ待ちのブランチ・サーバーの生存を確かめました。

## 2. 作る前に：業務の全体を調べた

作者の「質問の前に、俺の業務を全部把握して」という指示で、**サブエージェント3つを同時に**走らせました。
- 社内の資料（工程表・衛生検査・人員配置・シフト・レシピ・原価・棚卸）を読む係
- 過去の Claude セッションの記録を読む係
- Outlook のメール（8〜11月）から受発注の実態を読む係（読むだけ）

結果は「業務全体像」「現場条件（設備・人数・包装・材料と包材）」「類似システムの調査」の3つの文書にまとめ、各担当の初期データや設計の根拠にしました。

## 3. 作者のレビューで方向を変えた

一晩目の版を見た作者の評価は「仕組みはいい。でも実際に1年使うことを考えると全然ダメ。大枠だけ作りました感がある」。
これを要件にして、次を全員で作り直しました。
- 保存を JSON ファイル → SQLite（追加パッケージなしの node:sqlite）
- マスタ（商品・レシピと工程・設備と人員・取引先・仕入先・材料・包材・配送の便・定期注文・FAX の様式）を、画面で1件ずつ直せて、CSV で一括登録できるように
- 工程表に設備・人員の制約（ミキサーの同時使用・分割機の能力・霜取りの時間・人数不足）
- 画面を左メニューの構成に、色を自社の色（赤と白）に、「老人でも押す所が分かる」を基準に

## 4. 使った Claude Code の機能

- 並行セッションと SendMessage（担当どうしの直接のやりとり）
- git worktree（担当ごとの作業場所）
- サブエージェント（業務調査、類似システムの調査）
- スケジュール実行（30分おきの見回り）
- MCP：Gmail、Outlook（読むだけ）、Chrome（インフォマート・LINE Developers・Apps Script の画面を開くところまで。パスワードは作者が入力）、ターミナル
- Skills：claude-api（Claude API の使い方）
- 各担当のセッションの中で使った機能は、各担当の作業記録（01〜05）に書いてあります。

## 5. 守ったルール

- AI は「読み取り」と「要確認の印付け」まで。値を直すのは人。読み取った元の値と、人の修正履歴は必ず残す。
- 発注書は「下書き → 人が承認 → 送信」。承認なしでは送らない。
- 本物の取引先に届く送信・パスワードの入力・公開・課金は、必ず作者に回す。作者に頼むときは「画面を開いて、入力するだけ」の状態にしてから。
- 公開リポジトリなので、実在の取引先名・個人名・単価・レシピは入れない（社内資料の数字は、社名を架空にして形だけ使う）。

## 6. つまずいたこと

- パソコンのメモリ（7.6GB）に対してセッションが7つ同時に動き、開発サーバーやテストが落ちた → 常時動かすサーバーを1つに絞り、テストの並列数を下げた。
- 開発サーバーが worktree まで見張って画面が 9〜35 秒かかった → 本番用は本番モード（build → start）にして 0.05 秒に。
- 夜中にパソコンが眠り、5時間止まった。データベースの作り直しで本番の LINE の記録が消えた → 元のファイルから復元し、「デモを最初から」を2段の確認にした。
- 自動モードの安全ルールで止まる操作（トンネルの起動、別の AI エージェントの起動、守りを弱める設定）は、迂回せず作者の判断に回した。
