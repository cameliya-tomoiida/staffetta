## 2. Claude API の使い方（多言語）

- 場所: `src/i18n/translate.ts`（サーバー側だけ）
- モデル: `claude-sonnet-5-5`（短い言葉の翻訳なので、読み取り用の大きいモデルは使わない）
- 呼び方: `client.beta.messages.parse()` と **Structured Outputs**（Zod スキーマ → `betaZodOutputFormat`）。`{ items: [{ ja, text }] }` の形で受け取り、頼んだ言葉以外は捨てる
- まとめて1回: 画面を開いたとき、その日に出る名前（商品名・生地名）のうち**辞書に無いものだけ**を、言語ごとに1回のリクエストで訳す
- 保存して使い回す: 訳は `src/i18n/machine.json` に保存し、次からは API を呼ばない（同時に開いても訳が消えないよう、書き込みは1つずつ）。9言語 × 17語がたまっている
- 「機械翻訳」と出す: 保存した訳には1語ずつ「機械翻訳」の印。人の確認が済んでいない辞書の言語も、ページの上に「機械翻訳の言葉は、まちがっていることがあります」と出す
- 止めない: API キーが無い・失敗したときは日本語のまま出す（画面は止めない）
- 決まった言葉（見出し・工程名・単位・「翌」「前日」など）は API を使わず、`src/i18n/dict.ts` の辞書から出す。辞書の下書きも Claude（このセッション）が書いた。各国のスタッフが確かめたら `reviewed: true` にして印を消す

### 指示の工夫（試して直した）
- **用語集を一緒に渡す**: 辞書の「生地・粉・数・ミキシング・ホイロ・焼成」の訳を用語集として渡し、「同じ日本語には同じ訳」と指示。ミャンマー語で「生地」が「麺」と訳されていたのが直った
- **数字と単位は変えない**: ミャンマー語・ネパール語で「23cm」「180g」がその国の数字（၂၃・२३）に変わっていた。重さやサイズを読み間違えないよう、「数字は 0〜9 のまま」「cm・g・kg・L と OEM はそのまま」と指示し、まちがっていた訳を消して訳し直した
- **商品名の固有の部分は音で残してよい**（「超じゅく」を意味に訳さない）
- **やさしい日本語**は「漢字を使わず、ひらがな・カタカナで、外国人の新人スタッフが読める短いことば」と指定

## 3. 試行錯誤して直したこと

- **ことばを覚える cookie が効かなかった**: cookie の名前の定数を `"use client"` のファイルから書き出してサーバー側で読んだら、値ではなく「クライアントの参照」になっていた。定数を共通のファイル（`src/i18n/langs.ts`）へ移して直した
- **「今日やること」の数がお客さんの画面に混ざるおそれ**: 共通のレイアウトは LINE のお客さん用の画面（/liff）でも使われる。レイアウトで数を作ると、隠していても HTML に入ってしまう。そこで数は `/api/today` から工場の画面だけが取りに行く形にした（トンネル経由の外からのアクセスは①の `proxy.ts` で 403）
- **発注書の承認**: 画面から送られた中身を信じず、サーバーで注文から下書きを作り直して保存してから承認する。承認後に注文が変わっても、承認した中身を表示する
- **サーバーの処理のエラーが画面で読めない**: 本番ではエラーの文が隠れるため、`{ ok, error }` を返す形にした
- **印刷した発注書に自社のお客さんの名前が載る**: 画面の内訳（どのお店に何袋）は社内向け。印刷用 CSS で仕入先に送る紙からは消した
- **LINE の注文でお店が分からない**: 初めてのお客さんの注文は取引先が空のまま届く。受注一覧の確定のときに、候補から選べるようにした（文字入力はさせない）
- **Tailwind が worktree を読みにいく**: worktree がリポジトリの中（`.claude/worktrees/`）にあるため、Tailwind v4 がそこの node_modules まで読みにいき、画面全体が 500 になることがあった。①が `globals.css` に `@source not "../../.claude";` を足して直し、②はその1行を残したまま作業した
- **Next.js 16**: `next.config.ts` の `cacheComponents` などは①が最初に外していた。②の画面は保存データを毎回読む（`connection()`）ので、その前提のまま作った。`searchParams` は Promise なので `await props.searchParams` で読む
- **確認のやり方**: Claude Code のブラウザ（アプリ内のブラウザ）でタブレット幅 1024・スマホ幅 375 にして開いた。画面写真が撮れないときは、要素の幅や位置をスクリプトで測って、横にはみ出していないかを確かめた。テンキーの操作を試すときは、押すたびに少し待たないと前の数が残ることも分かった（テストのやり方の問題で、アプリの問題ではない）

## 4. Claude Code の機能で使ったもの・使っていないもの

### 使ったもの
- **git worktree**: このセッションは専用の worktree・ブランチで作業し、他の担当とファイルがぶつからないようにした。master は進行役がマージし、②は区切りごとに `git merge master` で取り込んだ（push はしていない）
- **セッション間のメッセージ（SendMessage）**: 進行役のセッションから仕事を受け、区切りごとに報告した。①④への提案も進行役経由で伝えた
- **共有のメモフォルダ**: 報告の長い内容を置いた
- **アプリ内のブラウザ（Browser pane）**: `.claude/launch.json` から開発サーバー（ポート 3101）を起動し、画面を開いて、タブレット幅・スマホ幅・A4 幅（794px）で確かめた。印刷用 CSS は、画面にそのまま当てて紙の見え方を確かめた
- **ファイルの読み書き・検索、シェル（Bash）**: 型チェック（`tsc`）、lint、③のテスト（vitest）を区切りごとに実行
- **タスクリスト**: 作業の順番を画面に出して進めた

### 使っていないもの
- サブエージェント（Agent ツール）・ワークフロー: 使っていない（このセッション1つで作業した）
- Plan モード・hooks・スキル: 使っていない
- Figma などのデザインツールの連携: 使っていない（デザインはコードの中で決めた）
- ユーザーの Chrome（Claude in Chrome）: 使っていない（アプリ内のブラウザだけ）

## 5. 守ったルール

- **AI がするのは読み取りと要確認の印まで。値を直すのは人**: 受注一覧の確定は人がボタンを押したときだけ。数量はテンキーで直し、AI が読んだ元の値（read）はそのまま、人の修正は edits に残る。0 にした行も消さずに残す
- **発注書は 下書き → 人が承認 → 送信**: 承認ボタンを押すまで送れない。承認には人の名前が必要。送るのは人で、送ったあとに「送った」を押す
- **お客さんへの LINE は、文面を見せてから人が押したときに1回だけ**
- **画面はタップ＋テンキー／選ぶだけ**: 担当者・お店・言語はすべて選ぶ形にした
- **高齢の人・外国人スタッフ向け**: 大きな文字とボタン、紙に近い見た目、やさしい日本語、9言語。色だけに頼らず必ず文字も出す
- **公開リポジトリ**: 取引先・商品・単価・レシピは架空のデータだけ。この記録にも実在の社名・個人名は書いていない
- **他の担当のファイル**: 共通の型（types.ts）と計算（src/lib）は変えなかった。①の FAX 画面も変えず、直したい点は提案として書いた。⑤の取り込み・送り出しは、処理を変えずに見た目の部品だけ差し替えた
