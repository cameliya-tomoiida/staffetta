# 「要確認の理由」の文言を、やさしい日本語にそろえる案（②デザイン・2026-11-05）

対象：受注一覧（/orders）、FAX の確認画面（/fax/[id]）、取り込み（/import）、LINE受付（/line）で、黄色の「要確認」の行に出る一言。
この文書は案だけを書いている。実際に直すのは、Codex の UX 改善がマージされたあと。各入口の担当（①④⑤）と相談して進める。

## 1. 今どうなっているか

理由の文は、入口ごとに別々の人と AI が書いている。言い方・長さ・むずかしさがそろっていない。

| 書いているところ | 今の文の例 | 気になる点 |
|---|---|---|
| FAX（AI・`src/lib/fax-reader.ts` のプロンプト） | 「訂正あり 20→25」 | 短くてよい。ただ「訂正」はむずかしい |
| FAX 確認画面（①） | 「読み取りの自信が低め（62%）」 | %は現場の人に意味が伝わりにくい |
| メール（AI＋⑤ `email/import.ts`） | 「入数が不明・品名の対応が推測・本文と添付で数が違う」「変更前 20」「元の注文が見つかりません」 | 「対応が推測」が分かりにくい。「・」でつなぐと長くなる |
| LINE（AI・`line/reader.ts`） | 「納品日の記載なし」「商品の対応が推測」 | 「記載」「対応」がむずかしい |
| シート（⑤） | 「列見出しが様式にありません（商品と入数を確認）」 | 「様式」がむずかしい |
| インフォマート（⑤） | 「商品コード X が当社の商品にありません」「発注元 Y が得意先にありません」 | 言いたいことは明確。少し長い |
| 取引先サイトの CSV（⑤） | 「コード変換表にない商品コード X」「当社の商品にひも付いていません」「前回 10 → 今回 12」「今回の CSV にありません（前回 10）」 | 「コード変換表」は事務の言葉 |
| 見本（②） | 「概数の注文。当日12時に確定の連絡が来る予定」 | 「概数」がむずかしい |

## 2. 書き方の決まり（案）

1. **1つの理由は1行・30文字くらいまで**。2つあるときは2行に分ける（「・」でつながない）。
2. **はじめに「何が」、おわりに「どうする」**。例：「数が 2つ 書いてあります。どちらか えらんでください。」
3. **むずかしい漢語を使わない**。言いかえの表：

   | 使わない | 使う |
   |---|---|
   | 訂正あり | 書きなおしが あります |
   | 記載なし | 書いて ありません |
   | 対応が推測 | 商品が 合っているか 見てください |
   | 概数 | だいたいの 数 |
   | 様式 | いつもの 注文書 |
   | 差分・変更前 | 前は ○○、今は ○○ |
   | 当社 | うち（工場） |
   | 得意先 | お店（取引先） |
   | コード変換表 | 商品の つなぎ表 |
   | 自信が低め（62%） | 読みにくい ところが あります |

4. **数字はそのまま、単位を必ず付ける**（「20→25」ではなく「20個 → 25個」）。
5. **AI のせいにも人のせいにもしない**。「まちがい」ではなく「見てください」と書く。
6. ふりがなは付けない（画面がせまくなる）。そのかわり、上の言いかえで漢字を減らす。

## 3. 言いかえの案（よく出るもの）

| いまの文 | 新しい文（案） | 理由の種類（コード案） |
|---|---|---|
| 訂正あり 20→25 | 書きなおしが あります（20個 → 25個） | `rewritten` |
| 丸の選択（白・黒） | ○が ついている方を 見てください（白／黒） | `circled` |
| 読み取りの自信が低め（62%） | 字が 読みにくい ところが あります | `low_confidence` |
| 商品の対応が推測 | 商品が 合っているか 見てください | `product_guess` |
| 入数が不明 | 1袋に 何個 入っているか 見てください | `pack_unknown` |
| 単位があいまい（「本」など） | 数え方（個・本・袋）を 見てください | `unit_unclear` |
| 納品日の記載なし | とどける日が 書いて ありません（あしたに しています） | `no_date` |
| 本文と添付で数が違う | メールと 添付で 数が ちがいます | `mismatch` |
| 変更前 20 | 前は 20個、今は 25個 です | `changed` |
| 元の注文が見つかりません | 変える前の 注文が 見つかりません | `original_missing` |
| 列見出しが様式にありません | いつもの 注文書に ない 商品の 列が あります | `unknown_column` |
| 商品コード X が当社の商品にありません | 商品の 番号 X が、うちの 商品に ありません | `unknown_code` |
| 発注元 Y が得意先にありません | 注文した お店 Y が、お店の 一覧に ありません | `unknown_customer` |
| 今回の CSV にありません（前回 10） | 前は 10個 ありましたが、今回は ありません（取消かも） | `removed` |
| 概数の注文。当日12時に確定の連絡が来る予定 | だいたいの 数です。当日の 12時に 本当の 数が きます | `approx` |
| 「いつもの」の中身が分からない | 「いつもの」が 何か 分かりません。前の 注文を 見てください | `usual_unknown` |
| 聞き取れない（17？70？） | 数が 聞きとれません（17か 70） | `unheard` |

## 4. しくみの案（文をそろえ、のちに多言語にもする）

- 今の `ReadValue.attention`（自由な文）は、そのまま残す（AI が書いた元の文は消さない決まりのため）。
- そのかわり、各入口で **理由のコードと数字** も一緒に持つ。例：
  `{ code: "rewritten", from: 20, to: 25, unit: "個" }`
  → 画面は `src/i18n/` の辞書から文を組み立てる。コードが無い（AI の自由な文だけ）ときは、今までどおり文を出す。
- 型を足す必要があるので、`types.ts` の変更として進行役に相談する（②は types.ts を直さない）。
  - 案：`ReadValue` に `reasons?: { code: string; [k: string]: string | number }[]` を足す。
- AI のプロンプト（fax-reader・line/reader・email/reader）にも、上の「書き方の決まり」と「コード」を渡し、コードを選ばせる。文は短いやさしい日本語で書かせる。

## 5. 進める順番

1. この表を担当者に見てもらい、言い方を決める（現場の人に通じるか）。
2. 画面側（②）：`%` の表示をやめる、「・」でつながず行を分ける、をすぐ直す（Codex のマージのあと）。
3. 各入口（①④⑤）：import の固定の文を、3. の新しい文に置きかえる。
4. AI のプロンプトに「書き方の決まり」を足す（①④⑤）。
5. types.ts に `reasons` を足すかを進行役と決め、決まったら多言語にする。
