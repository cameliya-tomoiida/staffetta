# 3100（本番モード）の入れ替え

3100 は、担当者の確認・本物の LINE・Gmail からの FAX を受ける本番の口です。`next start`（本番モード）で動かしている。master が進んだら、ビルドして入れ替える（①の担当）。

## やり方（止まるのは数秒・ビルド中も 500 を返さない）

`.next` は動いている 3100 が使っている。そのまま `npm run build` すると、ビルドの間 `.next` の中身が入れ替わり、入れ替えまで 3100 が 500 を返す（11/5 に一度起きた）。そのため、別の出力先にビルドしてから入れ替える。

1. 別の出力先にビルドする（3100 は動いたまま）
   ```
   cd C:\work\juhacchu-hub
   set HUB_DIST_DIR=.next-stage
   npm run build
   ```
   - `next.config.ts` の `distDir: process.env.HUB_DIST_DIR || ".next"` で出力先が変わる。
   - Windows で、まれに「Reading source code for parsing failed」や「UNKNOWN: lstat」でビルドが落ちる。ファイルの読み取りが一瞬つかえるだけなので、もう一度ビルドすれば通る。
2. ④（LINE）に一言かけてから、3100 を止める（`juhacchu-hub-prod` を止める）
3. 入れ替える（数秒）
   ```
   rmdir /s /q .next-old
   ren .next .next-old
   ren .next-stage .next
   ```
4. 3100 を起動する（`.claude/launch.json` の `juhacchu-hub-prod`。`next start -p 3100`）
   - 型の設定を戻す: 別の出力先にビルドすると、`next-env.d.ts`（git に入らない）が `.next-stage` を指すように書き換わる。入れ替えのあとに `npx next typegen` を1回実行して、`.next` を指すように戻す（これをしないと `tsc` で RouteContext などが見つからない。動いている 3100 には影響しない）。
5. 確かめる
   - 左メニューの全ページを開き、200 であること、エラーの画面（digest・Application error）が無いことを見る。200 だけでは分からない。サーバーから client の関数を呼ぶ不具合は、ページを開いて初めて落ちる。
   - 受信箱のサムネイルが描けること。
   - LINE の記録・本物の FAX がそのままであること。
6. 問題があれば、止めて `.next` と `.next-old` を戻せば、前の版にすぐ戻せる。

ビルドの出力は、別の名前のフォルダに移しても動く（11/5、`.next-stage` を別の名前に移して起動し、全ページとサムネイルを確かめた）。

## 気をつけること
- 本番モードはファイルを見張らない。コードを変えても、入れ替えるまで 3100 には入らない。
- 起動すると、5分ごとの判定（`src/instrumentation.ts` → `src/lib/scheduler.ts`）が始まる。確かめ用に別のポートで `next start` するときは、`HUB_SCHEDULER=off` を付ける（同じ DB に、判定が2重に走らないように）。
- `data/hub.sqlite` は本物のデータ。入れ替えでは触らない。DB の移行が入る版のときは、先に `VACUUM INTO` で写しを取る。
