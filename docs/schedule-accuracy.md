# 工程表の精度：実際の1日と比べて（2026-11-05）

工場の資料（工程表・人員配置表・作業指示書・製造会議の要約・統合製造計画）から、ピザラインの「ある1日」を取り出し、
同じ注文をアプリに入れて工程表を比べました。取引先・個人の名前は伏せています。
数字そのもの（実データ）はリポジトリに入れず、本番の DB にだけ入れました（`scripts/import-real/` で取り込み）。

## 比べた日

- 実際：月曜。ピザクラスト 23cm を **約1,800枚**（ラインの1日の上限いっぱい）。
  - 前の日（1日目）：計量 → ミキシング → 1次発酵 40分 → 分割・丸め・箱取り（4人・1ロット400個を40分）→ 2次発酵（室温20℃・9時間、夜のあいだ）
  - その日（2日目）：**7:00〜24:00**。伸ばし・鉄板のせ（2人）→ ジェットオーブン（1人）→ ショックフリーザー（霜取り 17:00〜17:40 は使えない）→ 検品・包装・金属検査・梱包（1人）。ラインの最低は4人。
  - 班：朝班 2人 7〜18時、夜班 2人 13〜24時、スポットの人 7〜14時 2人・18〜21:30 1人・21〜24時 2人、学生 17〜22時 1人。
- アプリ：同じ生地・同じ1,800枚を、同じ納品日で計算（`scripts/import-real/day.ts`）。

## ずれ（直す前）

| | 実際 | アプリ（直す前） | ずれの理由 |
|---|---|---|---|
| 1日の長さ | 7:00〜24:00 | 8:00〜18:25（見本のマスタ）／ 8:00〜翌1:40（原価表の工程をそのまま入れた場合） | 下の3つ |
| 工程のつながり | **ロットごとに流れる**。伸ばした生地から順に焼き、冷やし、包む。全部の工程が同時に動いている | 1つの工程が全部終わってから次の工程（伸ばし3時間 → 焼成3時間 → 包装3時間…と縦に並ぶ） | 流れ作業の考えが無かった |
| 伸ばしの速さ | 2人で 1時間 約120枚（1,800枚を約15時間） | 見本は 4人で 1時間 600枚 | 見本の値が速すぎ。原価表の「人件費の基準」の時間は工程表の時間ではない |
| 人数 | 伸ばし2・焼成1・包装1 ＝ 4人 | 見本は 伸ばし4・包装3 → 人が足りない警告が多い | 配置人数を実際に合わせていなかった |
| 開始・設備の時間 | 7:00〜24:00 | 8:00〜18:00 の設備があった（本番の DB が古い見本のまま） | 古い見本のまま |
| 霜取り | 霜取りの40分は焼いたピザがラックで待つ | 「使えない時間にかかっています」の警告 | 流している途中に止まる、を表せなかった |

## 直したこと

1. **ロットで流す**（計算）：ラインに「流すロット（個）」を足しました（`LineMaster.lotSize`、マスタの列「流すロット（個）」）。
   入れると、当日の工程は「前の工程の最初のロットが終わったら次の工程を始める」「終わりは、前の工程の最後のロット＋1ロット分より後」で並びます。
   発酵・冷却など待つだけの工程は、ロットごとに同時に進みます。空なら今までどおり（見本・テストの結果は変わりません）。
2. **流している途中の止まり**（計算）：ロットで流す工程が設備の使えない時間帯（霜取り）にかかるときは、その分だけ止まって終わりが延びます。工程に「○分 止まる」と書き、警告にはしません。
3. **本番の DB の値**（データ。リポジトリの外）：ピザラインの開始 7:00・流すロット 40枚（ラック1台ぶん）、ピザの設備の時間 7:00〜24:00・霜取り 17:00〜17:40、班と配置人数（伸ばし2・焼成1・包装1）、23cm の生地の工程（工程表の時間：1ロット400個を分割40分・4人、2次発酵 9時間、伸ばし 1枚30秒 など）。

## 直したあと

| | 実際 | アプリ（直したあと） |
|---|---|---|
| 前の日 | 午後に仕込み → 夜のあいだ 2次発酵 | 13:00〜17:32 仕込み・分割 → 17:32〜翌2:32 2次発酵 |
| その日 | 7:00〜24:00 | **7:00〜23:36**（伸ばし 7:00〜22:00、焼成 7:20〜22:07、冷凍は霜取りで40分止まる、包装 〜23:31） |
| 人が足りない警告 | （足りている） | 出ない |

のこりのずれ（約25分）は、人が減る時間（12〜13時・17〜19時の休けい）に伸ばしをゆっくりにすること、最後の片付けの長さが資料に無いこと、です。

## まだ足りない考え（資料に数字が無いもの・これから）

| 考え | いま | 次にすること |
|---|---|---|
| 段取り替え・洗浄 | 工程ごとに「段取り・調整（分）」はあるが、**どの資料にも時間が書いていない**。商品が変わるときは責任者に声をかける、だけ | 現場で1回測る（生地が変わるとき・トッピングが変わるとき・終わりの洗浄）。生地が変わるときの段取りを、工程表の生地と生地のあいだに入れる |
| 休けいで人が減る | 班の人数は一定として見ている | 班に「休けい」の時間を持たせ、その時間は流れを遅くする |
| 冷凍庫の容量 | 見ていない（左の冷凍庫は約90ケースが上限、11月は外の倉庫も検討中） | 保管の工程に「冷凍庫のケース数」を持たせ、作りだめ（前の日に作っておく提案）と在庫の合計が上限を超えないか見る |
| 発酵の待ちの重なり | 前の日の仕込みは前日 13:00 から順に。発酵室・ラックの数は見ていない | ラック・発酵の場所の数を設備に入れる |
| ミキサー・分割機・オーブンの能力 | ミキサーの kg、オーブン1回の枚数は資料に無い（分割は「1分20個」のメモだけ） | 現場で測って設備のマスタに入れる |
| パンのライン | 逆算（納品時刻から）で組む。ロットで流す計算は前から組むラインだけ | パンにも 180〜240個のロットで流す計算を入れる（品質のために1ロット360個はやめた、という会議の決定に合わせる） |
| 資料どうしの食いちがい | 23cm の入数（20枚／40枚）、こね上げ（25℃／26℃）、冷却の基準（−20℃／−18℃）など | 工場長に確かめて、マスタを1つに決める |

## 追加（2026-11-05 午後）：人員配置表（スポットの人向けの資料）と比べて

工場の「人員配置表とスポットの人の作業指示書」には、30分ごとに、1人ずつの作業（成形／A 焼成〜冷却／B 検品〜保管／霜取り／休けい）と、
「必要」「実際」「過不足」の人数が書いてあります。これとアプリの「人が足りない時間帯」を比べました。

| | 配置表 | アプリ（直す前） | アプリ（直したあと） |
|---|---|---|---|
| 必要な人数 | 成形2・A1・B1 ＝ 4人（7:00〜24:00） | 同じ（配置人数のマスタ） | 同じ |
| 休けい | 朝班・夜班それぞれ1時間（班ごとに時間がちがう） | 休けいの考えが無い | 班に「休けい」を持たせ、その時間は人数に数えない |
| 足りない時間 | 1か所だけ「−1」（夕方の1時間。霜取りの時間とも重なる） | 出ない（工程の途中で始まる休けいを見落としていた） | **同じ1時間に「1人 たりません」** |

直したこと（計算）:
- 人数を数える区切りに、工程の始め・終わりだけでなく、**班の出入り・休けいの始め・終わり**の時刻も入れた。班と休けいは「始め以上・終わり未満」で数える（18:00 に帰る班は 18:00 からの区切りに入れない）。
- **段取り替え**（ライン「段取り替え（分）」）：同じ設備で、前とちがう生地に替えるときに、そのあいだをあける。前から組むライン・逆算のラインの両方。
- **1日の終わりの洗浄・片付け**（ライン「1日の終わりの洗浄・片付け（分）」）：その日のラインの最後の工程のあとに「洗浄・片付け」の工程を足す。
- **パンラインもロットで流す**：納品時刻から逆算するラインも、流したときの並びのまま、最後の工程が締めに合うように後ろに合わせる。
- **前の日の作業が当日の朝まで続くとき**（生地玉を冷凍庫で12時間 など）は、それが終わってから当日の作業を始める。
- **冷凍庫の容量**：設備の種類に「冷凍庫」と「入るケース数」を足した。その日に作る品物のケース数（商品の「ケースの入数」で割る）が超えたら注意を出す。前の日に作っておく提案（代わりの日）でも、冷凍庫に入るかを見る。
- どれも、設定が空なら今までどおり（見本・デモの結果は変わらない）。

本番の DB に入れた値（値そのものはここに書かない）:
- 段取り替え・1日の終わりの洗浄：作者の答えの値を、パン・ピザの両方のラインに。
- 休けい：配置表の班ごとの時間（まだ確定ではない。マスタの班の「休けい」で変えられる）。
- パンのロット：会議の決定（1ロットを小さくする）の値。
- 冷凍庫：仮の値（左の冷凍庫の上限から）。ピザ用の冷凍庫の本当の容量はまだ分からない。
- 23cm の入数・こね上げ温度：作者の答えにそろえた（食いちがっていた資料側も同じ値として扱う）。
- 生地玉の工程（工程表から）：前の日に 計量→ミキシング→1次発酵→分割・丸め→鉄板並べ→急速冷凍→冷凍庫で12時間、次の朝に 検品・梱包（別の担当2人）。

のこり:
- 班に「曜日」が無い（生地玉の梱包は曜日で時間がちがう・夜のスポットの人も曜日で30分ちがう）→ 班に「曜日」を足す。
- 配置人数は「ライン×工程の種類」で1つ（ピザクラストの包装1人と、生地玉の梱包2人を分けられない）→ 生地ごとの人数を優先する。
- 生地玉もピザラインの1日の上限（枚）に数えている。実際は別の作業なので、上限に数えない印が要る。
- 人が減る時間は「ゆっくり製造」で乗り切っている。アプリは「たりません」と出すだけで、流れを遅くする計算はしない。

## 実績との比べ：製品カードを「記入欄」にする案（作るかは後で決める）

製造日報は無い。代わりに紙の「製品カード」に、計量・ミキサーの担当が、温度・湿度・ドライイーストの賞味期限・こね上げ温度・時間などを書いている。
これを工程表の各生地の行に「記入欄」として出せば、紙のまま実績が残り、あとで計画とのずれを見られる。

- 工程表（印刷）の各生地の行の下に、1行の記入欄：
  `室温 ___℃ 湿度 ___% ／ イーストの賞味期限 ____ ／ こね上げ ___℃（目安 工程の条件） ／ ミキシング 始め __:__ 終わり __:__ ／ 分割 始め __:__ 終わり __:__ ／ 担当 ____`
- 目安の値（こね上げの温度など）は、工程の「条件・メモ」から自動で入れる。目安から外れたら丸で囲む、と書いておく。
- 画面（あとで）：同じ項目を入れる欄。入れた時刻は計画の時刻と並べて出し、ずれが大きい工程は「次から時間を直しますか？」と聞く（C2：人が承認してから工程のマスタを直す）。
- 置き場所：製造の実績（`recordProduction` の記録）に「製品カード」の項目を足す形（①⑤と相談）。

## 追加（2026-11-05 夜）：班の曜日・上限に数えない商品

- **班の「出る曜日」**（`ShiftMaster.weekdays`。空なら毎日）：製造日の曜日の班だけ人数に数える。曜日で時間がちがう班は、曜日ごとに1行ずつ。
  本番の DB には、人員配置表のとおり「夜のスポットの人（月・金 と 火〜木 で30分ちがう）」「生地玉の梱包（月・火 は朝早く、水〜金 は少し遅く）」「ピザの応援（月・火だけ）」を入れた。
  → 水〜金は、生地玉の梱包の担当がまだ来ていない朝早い時間に工程表が梱包を置くので「1人 たりません」が出る。実際は担当の来る時間にずらして梱包している。工程の「始めてよい時刻」を生地ごとに持たせるのが次（今は入れていない）。
- **商品の「ラインの上限に数えない」**（`ProductMaster.excludeFromDailyCap`）：はい の商品は、ラインの1日の上限（枚）に数えない。生地玉（別の作業で作るもの）に入れた。
  → ピザクラスト 1,800枚＋生地玉 390個 の日も「上限を超えています」が出なくなった（工程表の人数・冷凍庫の容量には、今までどおり数える）。
- のこり：1日の終わりの洗浄が 24:00 をこえると、その時間の班がいないので「たりません」が出る（実際は 24:00 までに片付けまで終わらせている）。伸ばしの速さを配置表の実績に合わせて少し速くするか、洗浄の時間を確かめる。
