# 受発注ハブ UX改善の依頼（Codex 向け）

あなたの担当は、このアプリの **使いやすさ** です。見た目を飾ることではありません。
まず「誰が、どんな場面で、何に困って使うか」を想像し、その人の悩みが減るように画面を直してください。

## このアプリは何か
愛知県の小さなパン・ピザ工場の「受発注ハブ」です。
FAX・LINE・メール・Googleスプレッドシート・取引先サイト・電話で届く注文を1か所に集め、
集計 → 入数変換 → 仕入先別の発注書 → 製造計画・工程表 → 材料の所要量と発注 と流れます。
ハッカソン作品で、11/6(金) に 3 分のデモ動画を撮ります。

## 使う人（この順に大事）
1. **事務の女性（60代）**。毎日、FAXと電話の注文を紙に転記し、夕方に電卓で集計している。
   パソコンは「決まった操作」しかしない。小さい文字が読みづらい。間違えると取引先に迷惑がかかるので慎重。
   悩み：紙とFAXを見比べて「1と7」を読み違える。どこまで入力したか分からなくなる。変更のFAXを元の注文に反映し忘れる。
2. **営業課長（50代）**。18〜19時に帰社し、その日の注文をまとめてふじみ（仕入先）のサイトに入力し、製造依頼の紙を書く。急いでいる。
   悩み：集計が合っているか不安。締め時刻に間に合うか気になる。どの注文がまだ確定していないか一目で知りたい。
3. **製造の現場スタッフ**。外国人（ベトナム・インドネシアなど）が多い。朝5時から動く。手が粉で汚れている。
   悩み：日本語の帳票が読めない。明日の製造量が前日に分からない。数字と工程の順番だけ分かればいい。
4. **工場長（60代）**。全体を見て、材料が足りるか、人が足りるかを判断する。
5. **お客さん（喫茶店の店主、70代など）**。LINE で注文する。スマホの操作は最小限。

## 守ること（変えてはいけない決まり）
- AIは「読み取り」と「要確認の印」まで。**値を直すのは人**。人が直した値を AI が上書きする UI にしない。
- 修正はタップ＋テンキー／＋−／候補から選ぶ。文字入力はなるべく無くす。
- AIが読んだ元の値と、人の修正履歴は見えるところに残す。
- 発注書は 下書き → 人が承認 → 送信。承認なしに送るボタンを作らない。
- 元のFAX（PDF）と読み取り結果を**左右に並べて**見比べる形は変えない（現場が紙で確認してきたため）。
- 公開リポジトリ。実在の会社名・個人名・単価は入れない。
- `src/data/types.ts`（共通の型）と `src/lib/`（計算）は変えない。画面側だけを直す。
- `src/app/fax/` と `src/components/PdfView.tsx` は別の担当が同時に触っている。直したい点があれば `docs/ux-notes.md` に提案として書き、コードは変えない。

## 直してほしいところ
対象は `src/app/orders/`、`src/app/plan/`、`src/app/purchase/`、`src/app/layout.tsx`、`src/components/ui/`、`src/app/globals.css`、`src/i18n/`。
- 「AIで作った感」のない、現場の道具らしい画面にする。装飾より、迷わないこと・読み間違えないこと。
- 文字と数字の大きさ、行間、タップしやすさ（指で押せる大きさ）。
- 「今、何を見ていて、次に何をすればいいか」が画面の上で分かること。
- 要確認の件数、締め時刻までの残り、未確定の注文が、開いた瞬間に分かること。
- 数字の読み違いを防ぐ工夫（桁区切り、単位の明示、強調）。
- 多言語の画面は、言葉を減らし、数字と記号で伝わる形に。
- 使うのはタブレット（横 1024）が主、スマホ（375）でも崩れないこと。
- 既存のクラス名（card / btn-primary / btn-ghost / pill）は残す。別の担当が使っている。

## 進め方
- 起動：`npm run dev -- -p 3105`。架空データで動く。
- 直す前に、上の5人それぞれになりきって各画面を1回使い、困った点を `docs/ux-notes.md` に箇条書きで書く。
- そのうえで直す。直した理由も `docs/ux-notes.md` に短く書く。
- 区切りごとにコミットする（push はしない）。コミットメッセージは日本語。
- `npm run lint` と `npx tsc --noEmit` が通ること。
